# 포인트와 결제 운영 기준

| 구분 | 고객 표시/사용 | 관리자 |
|---|---|---|
| 고객 충전 `paidPoints` + 쿠폰 적립 `freePoints` | 합산한 ‘주식교육영상 포인트’로 마이페이지 조회·교육영상 결제 | 충전·쿠폰 구분 잔액 조회 |
| 기존 사이트 `balance` | 표시·사용하지 않음 | 기존 보유액 읽기 전용 조회 |
| VIP | 카드 한 장 또는 카드별 금액을 정한 2~5장 분할 결제 | 전체 카드 승인 후 서비스·그룹 확인 |

교육영상은 카드, 주식교육영상 포인트, 카드+포인트를 사용합니다. 할인 쿠폰 적용 후 최종 금액과 포인트 잔액은 서버에서 다시 확인합니다. 고객 충전은 이지페이 승인 확인 후에만 적립하고, 포인트 쿠폰은 관리자 발급·대상·유효기간·수량·중복 사용을 확인해 적립합니다. 영상 할인 쿠폰을 포인트 쿠폰으로 바꾸어 적립하지 않습니다.

VIP는 포인트를 사용하지 않습니다. 카드별 금액 합계가 실제 상품 옵션 금액과 같아야 하며 일부 카드만 승인된 상태에서는 전체 서비스가 활성화되지 않습니다. 카드번호나 CVC를 윌클럽에 입력/저장하지 않고 이지페이의 고객 결제창을 이용합니다.

실제 카드 결제를 켜려면 프론트 서버에 KICC 가맹점ID·Secret Key 및 테스트/운영 API 주소를 서버 환경변수로 설정해야 합니다. `docs/이지페이_결제연동안내.md`를 참고하십시오. 실제 KICC 가맹점 값은 이번 작업에 제공되지 않아 실제 카드 청구·승인·환불 시험은 실행하지 않았습니다. 검증은 가짜 PG 응답을 주입한 자동 테스트이며 실제 상용 승인 완료를 뜻하지 않습니다.

프론트와 관리자는 같은 영속 MySQL 저장소를 공유해야 합니다. DB 없는 Vercel의 임시 파일을 영구 지갑·결제 기록으로 쓰지 않습니다. 승인 상태가 불명확하거나 일부 카드가 승인된 주문은 재조정/수동 환불 필요 상태로 보존하며, 화면에서 성공/환불 완료로 임의 처리하지 않습니다.

고객 지갑과 주문은 서버가 확인한 고객 ID와 관리자 회원 ID의 연결을 사용합니다. 기존 로그인 어댑터는 검증한 `user.memberId`를 반환하거나 회원 레코드의 `openId`를 실제 로그인 ID에 연결해야 합니다. 이름·닉네임·이메일만으로 다른 고객 잔액을 추측 연결하지 않습니다. 회원 연결이 없으면 결제·충전·차감하지 않고 연결 필요 오류를 표시합니다.
