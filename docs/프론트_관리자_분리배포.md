# 프론트와 관리자 각각 배포

## 전달 파일과 배포 대상

프론트 전용 ZIP과 관리자 전용 ZIP을 각각 제공합니다. 소스 기반은 동일하지만 각 ZIP의 `deployment.config.json` 기본 대상은 각각 `frontend`, `admin`으로 설정되어 있습니다. 따라서 페이지를 다시 만들거나 디자인을 변경할 필요가 없습니다. Vercel 프로젝트 두 개를 만들고 각 ZIP의 루트 폴더를 해당 프로젝트에 사용합니다. 한 Git 저장소를 두 Vercel 프로젝트에 연결하는 경우에는 각 프로젝트의 `WILLCLUB_DEPLOY_TARGET` 환경변수로 배포 대상을 지정하면 됩니다.

프론트 프로젝트는 `/`에서 기존 메인 디자인이 열리며 고객 메뉴와 교육영상·무료영상·쿠폰 조회/검증 API를 제공합니다. 프론트 배포에서는 관리자·전문가 API를 차단합니다. 관리자 ZIP은 `/` 접속 시 `/admin`으로 이동하고 기존 관리자 인증·업무 화면을 제공합니다. 관리자 사이트의 고객 페이지 이동과 메인 복귀는 프론트 사이트 주소로 연결됩니다.

푸터의 `WILLCLUB` 문구는 관리자 사이트로 이동합니다. 글꼴·배치·색상·원본 푸터·상담 버튼의 디자인은 그대로입니다.

## 프로젝트별 환경변수

프론트 프로젝트에는 `.env.frontend.example`, 관리자 프로젝트에는 `.env.admin.example`을 기준으로 Vercel 환경변수를 입력합니다. 예제의 `your-frontend`, `your-admin`은 실제 배포 주소로 바꾸세요.

프론트의 `WILLCLUB_DEPLOY_TARGET`은 `frontend`, `SITE_ORIGIN`은 실제 프론트 사이트 origin입니다. 관리자의 `WILLCLUB_DEPLOY_TARGET`은 `admin`, `SITE_ORIGIN`은 실제 관리자 사이트 origin입니다. 두 프로젝트 모두 `NEXT_PUBLIC_FRONT_SITE_URL`에는 프론트 주소를, `NEXT_PUBLIC_ADMIN_SITE_URL`에는 관리자 주소를 입력합니다. 주소에는 페이지 경로나 마지막 `/`를 붙이지 않습니다. `NEXT_PUBLIC_` 두 변수는 이동 주소일 뿐 비밀값을 넣지 않습니다.

각 프로젝트에서 Framework Preset은 Next.js, Install Command는 `npm ci`, Build Command는 `npm run build`, Output Directory는 기본값을 사용합니다. 환경변수를 변경하면 반드시 새로 배포해야 이동 링크에 반영됩니다. `SITE_ORIGIN`은 실제 사용할 Production/Preview 주소와 일치시켜야 합니다.

## 두 사이트의 영상·쿠폰 데이터 공유

영상과 쿠폰 변경이 서로 반영되려면 **두 프로젝트에 동일한 외부 MySQL `DATABASE_URL`**을 설정해야 합니다. 관리자에서 공개 영상을 등록·수정하면 프론트의 `/api/catalog`가 같은 DB를 읽고, 메인에는 최신 등록일순 4개가 표시됩니다. 프론트는 새로고침·창 포커스 복귀 시 목록을 갱신합니다.

외부 DB가 없으면 Vercel의 두 배포는 제공 seed의 읽기 전용 조회만 가능합니다. 관리자 변경을 임시 파일에 저장한 뒤 공유됐다고 표시하지 않습니다. DB 없이 관리자 변경·쿠폰 발급이 다른 Vercel 배포로 계속 유지되도록 만들 수는 없습니다.

관리자 웹사이트와 고객 웹사이트를 나눠도 보안상 관리자 로그인은 필요합니다. 공용 기본 비밀번호는 없으며 관리자 프로젝트의 실제 인증 어댑터 또는 OAuth·관리자 허용 목록을 설정해야 합니다. 상세 절차는 [Vercel 테스트 배포·관리자 설정](./Vercel_테스트배포_관리자설정.md)을 확인하세요. 두 사이트의 쿠키는 기본적으로 각각의 도메인에 보관되며 관리자 로그인했다고 고객 사이트의 회원 로그인까지 자동 처리되는 것은 아닙니다.

## 추후 단독 서버

각 폴더에서 Node.js 22 이상으로 `npm ci`, `npm run build`, `npm start`를 실행합니다. 사이트별 포트·도메인과 `SITE_ORIGIN`을 설정하고 공통 MySQL을 사용합니다. `WILLCLUB_DEPLOY_TARGET=all`로 한 서버에서 프론트와 관리자를 다시 함께 실행할 수도 있습니다.

Vercel 테스트에서 실제 대용량 강의 업로드는 제한됩니다. 이 어댑터는 요청·응답을 보수적으로 4MB까지 허용하며 큰 강의 파일은 단독 Node.js 서버에서 검증하세요. Vercel 업로드 테스트에는 외부 FTP와 영속 영상 메타데이터 DB가 필요합니다. 단독 서버에서는 기존 JNB 영상 업로드·호스팅 연동을 그대로 사용합니다.
